# Google Remote：HID 默认映射与高级学习

## 使用流程

主窗口默认只显示「遥控器 → 按键测试、按键配置、连接设备」，无需先进入学习页面。首次连接时，Google Remote 自动独占已确认身份的 Google 遥控器 HID 接口。若设备有**经实机验证并随 App 发布的内置码表**，同型号用户无需再学习。

若该型号没有内置码表：打开「设置 → 高级功能 · HID 按键学习」，启用高级开关，点击「进入按键学习」，逐个选中实体按键并采集真实 HID Report。关闭高级开关后，学习入口隐藏，但已学的码仍可用于日常操作。

## 映射备份

「设置 → 按键映射备份与导出」提供：

- **导出已学习 JSON**：另存可共享的 `.json` 文件；
- **复制 JSON**：直接粘贴到对话中；
- **导入备份**：重装时可以先导入旧版导出文件，界面确认后替换本机自定义码表；
- **清除本机学习映射**：经确认后清空用户覆盖码表，恢复当前型号的内置码表（如果已经收录）。

文件只包含协议版本、报告格式、设备型号/VID/PID/传输类型、生成时间和用户真实采集的按键名称 + Report ID + code。**不导出蓝牙 UUID、Mac 唯一标识、脚本、账号或动作库。** 无法产生 HID 事件的遥控器按钮保持缺失，不能填猜测数值。导入时校验文件大小、schema、重复按键、重复 code 和松开码 `0`。

## 开发者将导出映射升级为默认码表

1. 收到用户完整 JSON 后，校验 `schemaVersion` 与 `reportFormat`，检查 VID、PID、productName、transport。
2. 确认每项 `key` 对应独立真实采样的 HID Report，且 `reportID/code` 无冲突；区分 IR、电源、ATVV 语音等不能从普通 HID 获得的按键。
3. 在 `GoogleRemote/Sources/RemoteHIDProfiles.swift` 的 `RemoteHIDDefaultProfiles.profiles` 加入经过核验的 `RemoteHIDProfile` 静态实例，**不要猜测缺失码值**。
4. 运行 `swift test` 与签名 Release 构建，并在清空该型号本机用户覆盖的环境下确认：首次安装后自动加载内置码表、实体按键正确高亮与执行；不同 VID/PID 或型号不误使用。

有效映射始终按 **经验证的内置默认 + 用户本机覆盖** 合并，用户覆盖优先；不会把一个 HID code 分配给两个不同的虚拟按钮。删除用户覆盖后立即回退到对应内置默认值。

**已收录的首个默认码表（2026-11-06）：** 实体 G9N9N 导出的 JSON 已经过 schema/格式/设备 ID/重复码校验，录入 VID=6353、PID=37968、产品名 `Chromecast Remote`、`Bluetooth Low Energy` 的 14 个普通 HID 按键。对应 Report ID 均为 1：上=3、下=4、左=5、右=6、OK=7、返回=11、主页=10、静音=8、YouTube=14、Netflix=15、电源=1、输入源=17、音量+=12、音量-=13。

**语音助手是第十五个物理按钮，但当前没有 HID 报告编码，不能虚构。** 遥控器的麦克风请求由 ATVV 控制通道 opcode `0x08` 发出（需要 BLE ATVV 接收服务启用）。现在 ATVV 事件已独立连入首页实体按键高亮/日志，UI 也禁用了「语音助手」的 HID 逐键学习。它不会写进 HID JSON。这条 ATVV 反馈需要用户实机复测。

未来其他型号/不同 VID/PID 的设备仍需提供验证过的映射；没有匹配的内置 profile 时，用户可通过高级学习或导入备份配置。
